# 模型来源标签项目检查与修复记录

检查日期：2026 年 10 月 20 日。检查基线：`c04e2ba`，插件版本 `1.0.0`。

项目的主要问题集中在浏览器配置保存、异常数据处理和来源列表管理。修复保留现有标签展示和本地存储格式，并补充回归测试。修改仅保存在本地工作区，暂不提交 Git。

## 问题清单

| 编号 | 优先级 | 问题与触发条件 | 影响 | 修复方案 |
| --- | --- | --- | --- | --- |
| 1 | 中 | 多个页面各自缓存整份配置，再用旧快照写回 `localStorage` | 后修改的页面可能覆盖另一页面已保存的简称，其他页面也不能及时显示修改 | 监听存储事件；写入前读取最新配置并仅合并待保存的来源修改；支持 Web Locks 时串行保存 |
| 2 | 中 | 存储内容只检查外层对象，不检查每个来源名及简称的类型 | 对象类型的来源名可能成为 React 子节点，导致设置区渲染失败；非法简称可能进入输入框 | 逐项校验字符串、空白和长度，丢弃非法值；首次加载和跨页面同步使用同一校验规则 |
| 3 | 低 | 发现的来源超过 200 个，旧来源记录被移除，但其简称仍然保留 | 简称继续生效，却暂时失去编辑行 | 设置列表合并来源记录与简称的键；裁剪历史时优先保留已有简称的来源 |
| 4 | 低 | 浏览器拒绝访问存储或保存时容量不足，异常被静默忽略 | 用户看到修改生效，却不知道刷新后会丢失 | 保留内存修改，并在设置区显示中英文保存失败提示；后续修改或外部存储变化时允许重试 |
| 5 | 低 | 使用普通对象作字典，`__proto__` 会触发对象的特殊属性行为 | 该来源 ID 无法正常登记和保存简称 | 使用无原型字典保存来源及简称，统一按自有属性处理 |
| 6 | 兼容性 | 插件以优先级 `-1` 占用模型名称的 `single` 槽位 | 会覆盖其他模型名称插件，包括本机 Harness 内置的 `1017` 角标；展示不会自动叠加 | 在 README 说明该行为，保留现有来源标签的替换方式 |
| 7 | 维护性 | 没有自动化测试入口 | 后续修改容易重新引入配置丢失、异常数据和生命周期问题 | 添加无需安装依赖的 Node 测试，覆盖保存、同步、异常存储和卸载清理 |

原始问题位置：`client.js` 的 `readObject`、`writeObject`、`setLabel`、`recordSeenProvider`、`SourceEditor` 及槽位注册逻辑。

## 修复结果

问题 1 至 5 已完成代码修复。现有两个存储键及其 JSON 映射格式继续沿用，已有合法简称不需要手动迁移。

问题 6 已在 README 说明兼容性：来源标签继续替换模型名称槽位，不自动叠加其他插件的角标。问题 7 已新增 `test/client.test.js` 和 `npm test`、`npm run check` 两个开发命令，未引入第三方依赖。

保存采用待保存修改队列：界面立即更新，保存期间显示状态；成功保存的修改从队列移除，失败的修改保留在内存中并显示警告。后续修改或相关存储事件会重试；读取存储失败时，不用空快照覆盖原有配置。卸载时移除监听器并阻止等待中的保存任务继续写入。

## 验证结果与适用边界

`npm run check` 和 `git diff --check` 通过。`npm pack --dry-run --ignore-scripts` 打包预检通过，确认客户端、Host 入口、补丁、语言文件及本检查文档均在发布文件清单中。`npm test` 的 15 项隔离回归测试全部通过，覆盖以下行为：

- 来源发现、简称设置、尾随空格、恢复默认和重新加载。
- 旧页面合并不同来源的修改、Web Locks 下同时保存，以及同一来源的覆盖与删除。
- 非法 JSON、非法字段类型、长度限制和特殊来源 ID。
- 超过 200 个来源后简称仍可编辑，历史记录优先保留带简称的来源。
- 保存失败、读取失败、部分写入失败、锁请求失败，以及错误提示和恢复重试。
- 外部清空存储、忽略无关存储区域、存储访问权限变化，以及插件卸载和重新加载。

测试使用隔离的存储、模块加载器和 React Hook 替身，执行实际客户端入口及交互回调。本机 Harness `0.2.1-rc.2` 的打包源码提供了所用的两个槽位；真实界面的安装、交互布局与卸载回归尚未执行。

支持 Web Locks 的页面通过同一个锁串行保存；同一来源以最后保存的修改为准。不支持 Web Locks 的浏览器使用写前合并与存储事件同步，仍存在两个页面完全同时读写时的竞争边界。旧版本插件或其他不遵循该锁的代码同时写入相同存储键，也不受该锁保护。

修改已保存在当前工作区，未暂存、未提交 Git，也未更新已安装的 Harness 插件。

## 复核结论（维护者）

对上述 7 项修复逐项复核，实现与记录描述一致，未发现缺陷。补充验证：

- `npm test` 15/15 通过；变异测试：移除存储值逐项校验后，「stored values are validated」用例立即失败，证明测试有效。
- `client.js` 的模块 `id` 仍严格等于包名（`dsh-model-source-label`），槽位优先级 `-1` 与两处 `slots.inject` 注册保持原样，符合 Host 加载契约。
- 复核时修正：本项目的 `check` 原先只做语法检查（不跑测试），与 gateway 项目不一致，已统一为「语法检查 + 测试」。

发布版本定为 1.1.0：属行为修复，存储格式与安装方式保持向后兼容。
